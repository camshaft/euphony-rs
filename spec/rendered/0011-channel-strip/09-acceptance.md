## Listening tests and release {#acceptance}

Each calculation version and each built-in preset keeps a listening record. A listening test is
blind, in random order, with every condition level-matched, and presents the stage off, the starting
point, a setting an engineer made by hand on the same track, a deliberately poor setting so that a
listener who can't tell the conditions apart is noticed, and the starting point of the previous
calculation version. Listeners rate each condition on a scale against a hidden reference, or choose
between pairs. The corpus is licensed multitrack recordings across the roles and genres the musician
names, beside the musician's own tracks. The musician sets the criterion of acceptance. A release
checks the records, the declared delays, the names and models that need clearance, and the hold of an
assistant's change while the transport runs.

### EU-0011-165 {#EU-0011-165}

Each calculation version and each built-in preset MUST keep a listening record.

### EU-0011-166 {#EU-0011-166}

A listening test MUST be blind, in random order, with every condition level-matched.

### EU-0011-167 {#EU-0011-167}

A listening test of a starting point MUST present the stage off, the starting point, a setting an engineer made by hand on the same track, a deliberately poor setting, and the previous calculation version's starting point.

### EU-0011-168 {#EU-0011-168}

The criterion of acceptance of a listening test MUST be the musician's.

### EU-0011-169 {#EU-0011-169}

Until the musician sets a criterion, each listening result MUST be reported as unverified.

### EU-0011-170 {#EU-0011-170}

A regression of a calculation version against the previous version MUST be reported with the tracks it covers.

### EU-0011-171 {#EU-0011-171}

The musician's own tracks in a listening corpus MUST NOT leave the musician's computers.

### EU-0011-172 {#EU-0011-172}

A release MUST be refused where a built-in preset or a calculation version lacks, for a role the release supports, a listening record of that exact version and of the named corpus that meets the musician's criterion.

### EU-0011-173 {#EU-0011-173}

A release MUST be refused where a stage's measured delay differs from its declared delay.

### EU-0011-174 {#EU-0011-174}

A release MUST be refused where a character, a preset or the text of the interface carries a console maker's name without recorded legal clearance.

### EU-0011-175 {#EU-0011-175}

A release MUST be refused where a built-in character or preset includes a model fitted to a commercial unit without recorded legal clearance.

### EU-0011-176 {#EU-0011-176}

A release MUST be refused where an assistant's strip change can apply while the transport plays or records other than through the musician's own apply of the held proposal.

### EU-0011-177 {#EU-0011-177}

A prototype build MUST NOT be reported as accepted.

### EU-0011-178 {#EU-0011-178}

On comparable tracks, the offsets the musician keeps after a starting point SHOULD become smaller from one release to the next.

### EU-0011-179 {#EU-0011-179}

The size of the offsets the musician keeps MUST be reported, release against release, from the musician's own records, with the count of tracks it covers.
