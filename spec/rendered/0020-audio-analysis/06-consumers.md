## Results in musical work {#consumers}

Consumers receive accepted results as explicit musical values, converted with a stated unit system
and vocabulary. An ambiguous key or meter stays a candidate until someone chooses one reading. Note
events from transcription become editable events in a project only through preview and apply. A
live transform that uses analysis binds to one accepted result version when it is activated. A
prepared analysis curve can drive modulation with a declared sample alignment, lookahead, latency
and smoothing, through the same validation of dependencies and cycles as any other modulation
source. The comparison of captured hardware with its models can use measurements and estimates of
pitch and timing, though audio alone doesn't establish the original effects chain or synthesizer
settings. Preference learning receives corrections, acceptances and listening evidence, each linked
to its exact result, and decides by its own rules whether that evidence proposes a preference; a
tempo correction isn't evidence that the person likes that tempo. A catalog of samples can index
analysis results without running an analysis of its own.

### EU-0020-053 {#EU-0020-053}

A consumer MUST NOT turn a candidate key or meter into a fixed constraint until someone chooses one candidate.

### EU-0020-054 {#EU-0020-054}

Each conversion of a result into a musical value MUST state the unit system and the vocabulary it converts between.

### EU-0020-055 {#EU-0020-055}

A live transform MUST use the accepted result version that was selected when the transform was activated.

### EU-0020-056 {#EU-0020-056}

New analysis MUST NOT retune or remap notes that are held during a performance.

### EU-0020-057 {#EU-0020-057}

A live transform whose analysis dependency is missing or stale MUST show itself as unavailable unless the musician selected an earlier result version for it.

### EU-0020-058 {#EU-0020-058}

An analysis curve used as a modulation source MUST declare its sample alignment, lookahead, latency and smoothing.

### EU-0020-059 {#EU-0020-059}

A result that depends on audio after the current moment MUST NOT drive modulation in a live performance.

### EU-0020-060 {#EU-0020-060}

An analysis curve used as a modulation source MUST pass the same validation of dependencies and cycles as any other modulation source.

### EU-0020-061 {#EU-0020-061}

A correction or an acceptance of a result MUST NOT become a preference except through the rules of preference learning.

### EU-0020-062 {#EU-0020-062}

Evidence that analysis sends to preference learning MUST link the exact result it concerns.
