## Corrections and applying results to the music {#corrections}

A result is a suggestion. A musician, or an assistant the musician authorized, can correct it, and
a correction is a new revision of the interpretation, recorded with who made it and the evidence
behind it. The musician can accept an interpretation, the result as it stands or as corrected, and
later work reuses an accepted interpretation, such as a tempo map or a chord progression. Applying
an accepted interpretation to the music, such as a tempo map, note events or chords, is an ordinary
project command: it can be previewed, it names the revision of the project it expects, and it can
be undone like any other command. The musician can listen to the music with and without an
interpretation before applying it.

### EU-0020-023 {#EU-0020-023}

A result MUST NOT change the music of a project unless the musician applies it.

### EU-0020-024 {#EU-0020-024}

The system MUST keep a method's output, each correction of it and the accepted interpretation as distinct records.

### EU-0020-025 {#EU-0020-025}

Each correction MUST record the person or the assistant that made it.

### EU-0020-026 {#EU-0020-026}

Each correction MUST link the evidence it is based on.

### EU-0020-027 {#EU-0020-027}

The command that applies an accepted interpretation MUST be previewable before it is applied.

### EU-0020-028 {#EU-0020-028}

The command that applies an accepted interpretation MUST name the project revision it expects.

### EU-0020-029 {#EU-0020-029}

An applied interpretation MUST be undoable like any other project command.

### EU-0020-030 {#EU-0020-030}

The musician MUST be able to audition the music with and without an interpretation before applying it.

### EU-0020-031 {#EU-0020-031}

An accepted interpretation MUST be reusable by later work without the analysis running again.
