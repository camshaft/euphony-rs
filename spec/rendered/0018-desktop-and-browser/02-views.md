## Familiar views and shared commands {#views}

The main views follow the arrangement, mixer, piano roll and automation conventions that musicians
learned on established professional workstations, with a track list, an inspector, a transport,
rulers, an asset browser and the composition editor around them. Recording, punching in, looping,
routing, selection, undo and export are commands that every interface of euphony shares: a view
sends them, and doesn't define them. Familiar workflows are the aim; pixel identity with another
product isn't.

### EU-0018-008 {#EU-0018-008}

The desktop interface MUST provide an arrangement view, a mixer, a piano roll and an automation view.

### EU-0018-009 {#EU-0018-009}

The main views MUST follow the layout and navigation conventions of established professional music workstations.

### EU-0018-010 {#EU-0018-010}

The desktop interface MUST provide a track list, an inspector, a transport, rulers, an asset browser and the composition editor beside the main views.

### EU-0018-011 {#EU-0018-011}

A musician MUST be able to arrange tracks, edit notes and automation, mix, record and export from the desktop interface.

### EU-0018-012 {#EU-0018-012}

Recording, punching in, looping, routing, selection, undo and export MUST use the commands every interface of euphony shares.

### EU-0018-013 {#EU-0018-013}

A view MUST NOT define a command of its own that changes a project.
