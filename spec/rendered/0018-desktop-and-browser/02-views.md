## Familiar views and shared commands {#views}

The main views follow the conventions that musicians learned on established professional
workstations: the arrangement view, the piano roll and the automation view lay time out from left to
right under a ruler that marks the playhead; the mixer shows a channel strip for each track in the
order of the track list; and one command opens any main view from another at the selected track and
the playhead. A track list, an inspector, a transport, rulers, an asset browser and the composition
editor surround the main views. Recording, punching in, looping, routing, selection, undo and export
are commands that every interface of euphony shares: a view sends them, and doesn't define them.
Familiar workflows are the aim; pixel identity with another product isn't.

### EU-0018-008 {#EU-0018-008}

The desktop interface MUST provide an arrangement view, a mixer, a piano roll and an automation view.

### EU-0018-009 {#EU-0018-009}

From any main view, one command MUST open each other main view at the selected track and the playhead position.

### EU-0018-010 {#EU-0018-010}

The desktop interface MUST provide a track list, an inspector, a transport, rulers, an asset browser and the composition editor beside the main views.

### EU-0018-011 {#EU-0018-011}

A musician MUST be able to arrange tracks, edit notes and automation, mix, record and export from the desktop interface.

### EU-0018-012 {#EU-0018-012}

Recording, punching in, looping, routing, selection, undo and export MUST use the commands every interface of euphony shares.

### EU-0018-013 {#EU-0018-013}

A view MUST NOT define a command of its own that changes a project.

### EU-0018-096 {#EU-0018-096}

The arrangement view, the piano roll and the automation view MUST lay time out from left to right under a ruler that marks the playhead.

### EU-0018-097 {#EU-0018-097}

The mixer MUST show one channel strip for each track, in the order of the track list.
